# 量子ネットワークアイコン

> **English version**: see [README.md](README.md).

GUI シミュレータには [Van Meter らの研究](https://arxiv.org/abs/2112.07092) で提案されているネットワークアイコンを採用しています。アイコンはオリジナルの SVG 形式に加え、白背景および透過背景の PNG でも提供しています。アイコンは自由に利用可能で、論文等で図やトポロジを描く際に本アイコンセットを採用していただくことを推奨します。

現状、量子ネットワークトポロジ内のノードを表す 12 個のアイコンを提供しており、多くの異なる技術およびアーキテクチャをカバーします。
各ノードの簡単な説明を以下に示します。

## エンドノード

ここでの「エンドノード」は、アプリケーションが動作可能なノードを指します。これらのノードは接続セットアップ要求を発行でき、Bell pair や一般のグラフ状態など、もつれリソースを要求できます。
エンドノードのアイコンは四角形の枠線を持ちます。

### 計算ノード (COMP)

<img src="./icons_COMP_white.png" alt="computational node icon" style="height: 100px; width:100px;"/>

量子状態の測定が可能で、量子メモリへの保存も可能な計算用エンドノードです。
これにより機能性が大きく向上し、ブラインド量子計算のような高度なアプリケーションが可能になります。処理能力はノードによって様々で、シンプルなクライアントは単一キュービット状態の生成・保存・操作のみが可能なものから、進んだ量子サーバは大規模な多キュービットもつれ状態を生成でき、ユニバーサルなフォールトトレラント量子計算を実行できるものまであります。

### 測定ノード (MEAS)

<img src="./icons_MEAS_white.png" alt="measurement node icon" style="height: 100px; width:100px;"/>

受信した光子を（少なくとも 2 通りの方法で）測定するだけで、キュービットを保存しないノードは意外と有用です。このようなノードのペアは量子鍵配送を実行でき、また 1 つのこの種のノードを完全な COMP ノードに接続して、ある形式のセキュアなブラインド量子計算を実行する端末として機能させることもできます~\cite{PhysRevA.87.050301}。ただし、誤り管理能力はかなり限定されます。

### センサノード (SNSR)

<img src="./icons_SNSR_white.png" alt="sensor node icon" style="height: 100px; width:100px;"/>

センサノードはサイバーフィジカル動作（例: 干渉計のための参照フレーム、時刻同期）にもつれ状態を使います。これらのノードでは特に「時間がサービスの一部である」ことを意識してください。

### メモリノード (MEM)

<img src="./icons_MEM_white.png" alt="memory node icon" style="height: 100px; width:100px;"/>

メモリノードの主な機能は量子状態の長期保存です。基本的な状態処理機能を持つこともありますが、COMP ノードのような完全な量子計算を意図したものではありません。量子誤り訂正に対応する程度には高度になり得ます。

## 量子リピータノード

### 1G リピータ (REP1)

<img src="./icons_REP1G_white.png" alt="1G repeater node icon" style="height: 100px; width:100px;"/>

1G リピータ。常に 2 つのインタフェースを持ちます。最近の実験では一度に片方のみアクティブにできますが、一般化された形式では両方を同時にアクティブにできます。主タスクは物理キュービット上でのもつれスワップと、純化の形での誤り管理です。

### 2G リピータ (REP2)

<img src="./icons_REP2G_white.png" alt="2G repeater node icon" style="height: 100px; width:100px;"/>

2G リピータ。REP1 と同じくもつれスワップが主タスクですが、複数の物理キュービットからなる符号化された論理キュービットレベルで動作します。誤り管理は誤り訂正によって実現され、REP2 アイコンのチェックマークがそれを示します。REP2 は多数の物理キュービットを扱えるハードウェアを必要とし、より高度な計算能力を要します。

### ルータ (RTR)

<img src="./icons_RTR_white.png" alt="router node icon" style="height: 100px; width:100px;"/>

ルータ。実装上は複数のラインカードとバックプレーンで構成されることが多いですが、ネットワークアーキテクチャの観点では「ネットワーク動作を司る完全なプロトコルスイートを実行する」ことが重要です。典型的に RTR は 3 つ以上のネットワークインタフェースを持ち、ネットワーク境界を担当できます。境界では 1G/2G プロトコルを併話しつつ RuleSet を書き換える役割（接続要求のレスポンダ、または中継）を担うこともあります。

**注意: 一部の文献ではこれを switch と呼びますが、QuISP では「メモリを持たず光子を経路替えするだけのデバイス」を switch（後述の OSW）と呼びます。**

## サポートノード

### もつれ光子対源 (EPPS)

<img src="./icons_EPPS_white.png" alt="epps node icon" style="height: 100px; width:100px;"/>

もつれ光子対源。例として spontaneous parametric down conversion (SPDC) で実装されます。EPPS はもつれ光子対を生成するだけで、リンク端点で捕捉または測定する必要があります。地上設置でも衛星上でも使用でき、衛星の場合は地上の望遠鏡で光子を捕捉します。

### Bell State Analyzer (BSA)

<img src="./icons_BSA_white.png" alt="bsa node icon" style="height: 100px; width:100px;"/>

Bell State Analyzer は 2 つの光子をベル状態の 1 つに射影します。通常はメモリ-光子およびもう一方の光子-メモリのもつれをメモリ-メモリ間のもつれにスワップする用途で使われます。線形光学系での理論効率の上限は 50% です。BSA のハードウェア複雑度は使用するキュービット符号化に依存します。

### リピータグラフ状態源 (RGSS)

<img src="./icons_RGSS_white.png" alt="rgss node icon" style="height: 100px; width:100px;"/>

メモリレスリピータネットワークで使われるもつれ多者光子状態を生成します。生成したリピータグラフ状態の半分を近接ノードへ送信し、そこで光子が測定されます。

### Advanced Bell State Analyzer (ABSA)

<img src="./icons_ABSA_white.png" alt="absa node icon" style="height: 100px; width:100px;"/>

Advanced Bell State Analyzer。基本の BSA は常に同じ操作を行いますが、リピータグラフ状態に基づくオールオプティカル・リピータでは 2 光子測定と 1 光子測定が必要です。測定基底（測定種別）は事前の測定結果や論理符号化、リピータグラフ状態の構造に応じて動的に選択されます。
ハードウェア・ソフトウェア・プロトコル実装は BSA より大幅に複雑になります。

### 光スイッチ (OSW)

<img src="./icons_OSW_white.png" alt="osw node icon" style="height: 100px; width:100px;"/>

光スイッチ（ナノメカニカル等）は上記のノード種別に組み込まれることもありますが、ネットワーク内に単独で配置し、光子を測定せずにリンク間で経路替えすることも可能です。
